## c. How another system starts a job

There is no API in front of the engine today. A job is: files committed to the repo, then a `workflow_dispatch`, then
results read from a release and the committed cost record. Any system with a GitHub token that has `contents:write` and
`actions:write` on `Eouchi147/kinoforge` can do it with the REST API. (The web studio holds a `GITHUB_TOKEN` that can
commit to this repo; whether it can also dispatch workflows is unknown.)

```bash
# start
gh api -X POST repos/Eouchi147/kinoforge/actions/workflows/<file>.yml/dispatches -f ref=main -f inputs[<name>]=<value>
# status (the dispatch call returns no run id here: take the newest run of that workflow created after the dispatch)
gh api "repos/Eouchi147/kinoforge/actions/workflows/<file>.yml/runs?per_page=5" --jq '.workflow_runs[] | [.id,.status,.conclusion,.created_at]'
# outputs
gh api repos/Eouchi147/kinoforge/releases/tags/<release> --jq '.assets[] | "\(.id) \(.name) \(.size)"'
```

| Job | Brief (committed first) | Dispatch | Outputs | Status and cost |
| --- | --- | --- | --- | --- |

Example: `boards/restaurant-02/board.json` | `board.yml`, `board=<id>` | release `boards`: `<id>-<frame>.jpg`, `.cut.png`, `-move.mp4`, `<id>-board.log` | run status via API; `boards/<id>/ledger.json` (every call with `usd`), `boards/<id>/account.json` (key usage before and after, which lags) |

Important limits for automation:
- **A code-built ad is not brief-only today.** Each ad's `index.html` was written by a coding agent (Claude with builder
  subagents) against that ad's audio. Unmissed's admin cannot start one from a form until scenes become templates.
- No callback: the workflows do not notify anyone when they finish. A caller must poll.
- Outputs land in **public** releases and costs in **public** commits. Unsuitable for client material as it stands.
- Runners commit to `main` (ledgers, audio): `codead.yml` retries a pull-rebase-push up to 5 times, `board.yml` tries once; concurrent jobs can collide.

### The cleanest way for Unmissed's admin (recommendation, not built)
1. Unmissed admin creates a job record (job id, client, type, brief, cap) and stores client inputs privately.
2. A server function in Unmissed calls `workflow_dispatch` on the engine with only the job id and a signed URL to the brief
   (fine-grained token limited to Actions on the engine repo, kept as a server secret).
3. The workflow fetches the brief, runs, uploads outputs to private storage, and posts status, output links and the ledger
   total to an Unmissed webhook, signed with a shared secret (start, each paid step, done or failed).
4. The admin shows the preview with Approve and Reject. Approve is Sam's only step; delivery or publishing follows it.
5. Caps enforced twice: per job in the engine (already exists) and per client per month in the admin (new).

## g. Open problems, risks, known bugs, licences

### Open problems
- **Voices sound artificial.** ElevenLabs v3 premade voices via OpenRouter are the current limit (Sam, 16 Oct). Facts
  gathered on 16 Oct from OpenRouter's docs and model list (not tested): `/audio/speech` also offers Gemini TTS
  (`google/gemini-3.8-flash-tts`, multi-speaker dialogue, voice design, voice cloning), Fish Audio (`fish-audio/drama-3`
  directed multi-speaker scenes; `fish-audio/s2.1-pro`), ElevenLabs v4 (`elevenlabs/eleven-v4`), Microsoft MAI-Voice 2.1,
  ByteDance Seed Audio 1.0 (prompted, $0.15 per minute), OpenAI `gpt-4o-mini-tts`, MiniMax Speech 2.8, Deepgram Aura 2,
  Mistral Voxtral TTS, Kokoro. Multi-turn `input` (one generation for a whole conversation) works only on Gemini TTS and
  Fish Audio; `instructions` (delivery direction) on OpenAI, Gemini and Fish. Sources:
  https://openrouter.ai/docs/guides/overview/multimodal/tts.md and https://openrouter.ai/collections/text-to-speech-models .
  The container cannot reach openrouter.ai directly; model lists must be read on a runner or via web fetch.
- **Code ads are hand-authored.** Every scene is written by a coding agent; there is no template yet (see c).
- **Lyria scores do not follow the brief's structure.** Four of the five directions (all but v2) needed `music_offset`, a delayed copy (v3,
  `music_late.mp3`) or bar-aligned cuts (v5, `music_edit.mp3`). The beat tracker sometimes halves or doubles the tempo
  (v1 found 61.5 for 124 BPM; v4 143.5 for 72); builders checked with librosa.
- **Whisper words differ from the script** ("40", "the Saturday", a stray "You?"): The Call shows the script's words, timed
  by alignment.
- **Listening checks:** v1 weak ducking and a blip under the tagline; v4 interface sounds too quiet (v4 is dropped).
- **AI footage:** video models warp hands, crowds and small particles; the automatic re-render loop doubled costs on 15 Oct
  (fix the look, not the clip); `piece.yml` had 5 failed and 7 cancelled runs of 19.
- **Web studio:** videos 404 (not deployed), studio key nearly empty, director pipeline never run.
- **`showcase.yml`:** all runs failed (scene agent replies truncated), about $2.51 spent.

  other activity unrelated to the production, testing, deployment, or publication of the software project" of the repo,

- **Honesty:** Unmissed claims only in the site's words; no testimonials, ratings, counts, results or prices; demos say

## i. Recommendation: wiring KINOFORGE into Unmissed

**Keep separate**
- **The engine's code** (renderer, scenes, pipelines, ledgers) in its own repo, versioned on its own. It can stay public
  as code, with no client material.
- **Client data and outputs** in private storage owned by Unmissed (a private repo's releases or a blob store), never in
  this repo's public releases.
- **Production compute** off free GitHub-hosted runners on the public repo (terms and minute limit, see g). Options with
  known trade-offs: a self-hosted runner (a small cloud machine, or Sam's Mac when it is on), or a paid compute service.
  Which one: Sam's call.
- **Keys:** a production OpenRouter key with its own limit, separate from test spend. Sam adds keys himself.

**Merge**
- **Approval** into Unmissed's admin (one queue, Approve or Reject per job). Retire the KINOFORGE web studio's approval role.
- **Brand and claims:** Unmissed's `site.config.js` as the single source; the engine reads it instead of keeping a copy
  (`harness/shots/policies/unmissed.md` is a hand-made copy today).
- **Spend:** one ledger view per client and per month in the admin, fed by the engine's per-job ledgers.

**Build first, in order**
1. Fix the voice and finish Bento: it is the one ad Sam loves, and it becomes the first template.
2. The job contract: job id, type, brief, cap, callback; dispatch from an Unmissed server function; signed status and
   result callbacks; private output storage. Start with the two brief-driven jobs that already work (style board, code-ad
   render).
3. Turn Bento into a template driven by a brief (business name, services as tiles, colours, lines, voice), so a client ad
   needs no coding session. Then 9:16 and French variants of the template.
4. Move production compute and client storage to their private homes before the first real client job.
5. Then more templates (Type in Motion, Screen Story, The Call), then AI-footage ads only after a look passes Sam's style
   board, then social posts and brand kits.

**Park:** the film lanes, `director.yml`, `showcase.yml`, the web studio's director chat.
